## Method, because these mattered

- **Answer the question Tom asked, then check which question he answered.**
  His "Yes but with context..." answered the phone question, not all three;
  a relayed reading went to core before he corrected it.
- **Follow a failure to the node's journal.** "Won't play" was found from
  fi-1's `journalctl -u macha` (create, then a PATCH, then silence), and the
  server's source said which refusal fits. The server logs slow requests
  only, so a quick refusal is invisible there; the client's own notice now
  carries it.
- **Record machine load with any timing** (memory: shared-machine load).
- **Mutation-check every new test** before trusting it green; done throughout.
- **Deploys:** backup, additive rsync, then verify each node serves the bundle
  with a matching `shasum` and the `hls` chunk still answers.
